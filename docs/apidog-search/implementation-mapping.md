# Reqora implementation mapping

The Reqora directory was empty at the beginning of this task. The result is a new Electron + React + TypeScript prototype, using the user-selected electron-vite, pnpm, Tailwind, and Vitest stack. The workspace data in `src/search/demo.ts` is original synthetic data; no Apidog project contents or packaged implementation code are imported into the product.

This document separates reproduced behavior from Reqora design choices. Static evidence establishes what the shipped code contains; it does not establish that a particular account or screen executed every path.

## Behavior carried into the search core

| Apidog observation | Reqora implementation | Relationship |
| --- | --- | --- |
| A02 trims a query and checks case-insensitive substrings against each keyword. It is a predicate, with no fuzzy matcher or relevance score in that traced function. | `searchRecords` and `matchRanges` in `src/search/repository.ts` use a single trimmed literal query and keep the incoming record order. | Reproduces the traced matching approach. This is not token AND or fuzzy search. |
| A04 assembles HTTP endpoint keywords from ID, name, path, individual tags, folder ancestry names, and an optional project module name. | Search fields are `id`, `name`, `path`, `tags`, and `folder`; each tag and breadcrumb is checked separately. | Reproduces the principal HTTP endpoint keyword sources. The prototype has no project module entity or module-name field. |
| A03 collects folder names with a cycle guard. A08 records expansion before filtering and restores it afterwards. | `SearchResult.ancestors` contains root-to-parent IDs with cycle/missing-parent guards, providing a renderer seam for revealing a result. | The ancestry mechanism is a simplified Reqora data model. It must not be described as a port of Apidog's complete tree system. |
| A01 requires each active metadata category to pass, accepts any selected value within a category, supports exclusion, and fails missing metadata even in exclusion mode. | `SearchOptions.filters` and `searchRecords` implement these predicates for status, tags, maintainer, creator, and last editor. | Reproduces the traced predicate semantics with normalized string fields. Apidog's responsible/creator/editor IDs are simplified to the prototype's named metadata values. |
| A02 has a fallback that replaces `{parameters}` in endpoint paths with `[^/]+`, constructs a regular expression with `gi`, and tests the query. | `matchesParameterizedPath` recognizes a concrete path or an absolute HTTP(S) URL for a parameterized endpoint. | Related feature, deliberately changed semantics; see below. |
| UI-01/UI-02 save search-history strings under a named namespace/key and commit a unique newest-first list of at most ten on Enter. UI-03 has an IME composition guard. | `src/renderer/src/preferences.ts` provides ten-entry newest-first history. `App.tsx` defers search during composition and guards keyboard actions. The pure repository performs no storage operations. | The interaction is evidence-informed. Reqora trims saved queries; the observed Apidog handler stores its current keyword directly. Reqora's storage format and implementation are its own. |

Evidence A01–A09 is in [core-search-excerpts.json](evidence/core-search-excerpts.json). UI evidence, including exact snippets, UTF-16 offsets, and hashes, is in [ui-search-facts.md](evidence/ui-search-facts.md).

## Explicit Reqora choices and limitations

- **Selectable search fields are an addition.** `DEFAULT_SEARCH_OPTIONS` initially enables name, path, tags, ID, and folder names. The traced Apidog HTTP code assembles its keyword array directly; the evidence does not establish this five-checkbox settings UI in Apidog.
- **Record-kind filtering is an addition.** The prototype's `api`, `folder`, `schema`, `doc`, `case`, and `response` selections filter a unified local record list. Apidog's evidenced metadata controls are **status, tags, and maintainer by default**, with creator, last editor, and enabled custom fields available (UI-04/UI-05, A01). Reqora's record-kind selections are a separate filter, not a reproduction of those metadata controls. `MetadataFilters.tsx` separately exposes status, tags, and maintainer, plus tag exclusion/reset. The core also accepts creator/last-editor predicates; these two do not have visible controls. Enabled custom field filters are outside this prototype's model.
- **Record kinds simplify distinct Apidog models.** A05 shows HTTP cases remaining as children of an allowed endpoint during tree construction. Reqora lets its synthetic case and response records match independently. No claim is made that Apidog independently searches cases/responses with this exact model. The trace also contains separate HTTP request, RPC, document, and protocol adapters.
- **Tree presentation is simplified.** Reqora keeps its collection sidebar available, displays filtered hits with folder breadcrumbs, and reveals an opened hit's ancestors. It does not reproduce Apidog's recursive filtered-tree rendering or its automatic expansion snapshot/restore lifecycle.
- **Method exclusion has a specific scope.** Reqora displays HTTP methods but does not search them. That matches A04's HTTP endpoint keyword assembly. It does not reproduce the distinct ad hoc HTTP request adapter in A06, whose keywords include method.
- **The parameterized-path fallback is stricter.** Reqora escapes literal regular-expression punctuation, anchors the entire path, requires a nonempty parameter segment, and excludes `/`, `?`, and `#` from a parameter. For an absolute HTTP(S) URL, it uses the URL pathname and ignores its host/query. Apidog's A02 fallback is unanchored, does not escape the rest of the path, and uses `[^/]+`. For example, Reqora deliberately refuses `/v1/fileXjson/42` for `/v1/file.json/{id}`.
- **Highlighting is original rendering logic.** Match ranges refer to original UTF-16 text. Literal matches can be rendered as React text/spans; user text is not interpreted as HTML or a regular expression. A route-fallback hit highlights the complete path. The trace does not establish this exact highlighting policy in Apidog.
- **Description/body contents are outside the search fields.** Synthetic descriptions and example bodies can be shown in the detail pane, but they do not enter this search. This is a scoped API workspace search, not a full-text documentation engine. It does not implement Apidog's separately configured DEFAULT/LOCAL/ALGOLIA published-documentation engines (UI-10).
- **Blank queries return all permitted records.** With an empty trimmed query, the repository returns all records allowed by the kind selection and active metadata conditions, including when no text field is selected. The renderer shows its exploration/recent-search screen when blank input also has no narrowed kind selection or active metadata filter; otherwise it shows matching filtered records. A nonempty query with no selected field produces no matches. These are explicit Reqora contracts.
- **The repository is local and replaceable.** `createMemorySearchRepository` clones input/output, exposes promise-based `getAll`/`search`, supports replacement, and checks cancellation before computation. No search IPC, remote API request, account authentication, or search backend is implemented. This is a seam for a future adapter, not evidence about Apidog's storage architecture.
- **Navigation shortcuts are Reqora decisions unless separately evidenced.** The observed Ctrl/Meta+F expression in UI-09 belongs to a separate find-in-page IPC feature. It must not be cited as evidence for a workspace-search launch shortcut, command palette, or result-list arrow-key behavior.
- **The screen layout and debounce are original.** Reqora uses a search/results/detail workspace, Ctrl/Cmd+K to focus search, arrow-key result selection, Enter to open, Escape to clear, and a 150 ms search delay. These choices must not be attributed to the inspected Apidog workspace implementation. In particular, Apidog's observed 800 ms delay belongs to find-in-page (UI-09).
- **Persistence is limited to preferences/history.** The renderer uses versioned `reqora.search.history.v1` and `reqora.search.options.v1` localStorage keys and recovers from invalid/unavailable storage. The synthetic workspace is initialized by the local memory repository; this prototype is not a complete persisted API editor.

## Verification scope

`src/search/repository.test.ts` covers substring/query behavior, independent keyword boundaries, selected fields and record kinds, metadata filter combinations/exclusion, omitted description/body/method content, ancestry, empty input/workspaces, concrete URL/path matching, escaped/anchored path behavior, safe Unicode text ranges (including contextual Greek casing), replacement, caller mutation isolation, and cancellation. Those are executable Reqora checks; they do not constitute runtime tests of Apidog.

The exact final check results and renderer verification are recorded in the main task report. The evidence collectors are reproducible static analyses of the installed package; this mapping deliberately does not present static source inspection as an observed network call or an executed UI interaction.
