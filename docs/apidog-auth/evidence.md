# Apidog request authentication: static evidence

Investigation date: 2026-10-16. This is a clean-room evidence ledger for Reqora's request-authentication feature. It contains facts from a **literal scan** of Apidog's packaged JavaScript. No Apidog code was executed. Facts are separate from inferences. Excerpts are short verbatim prefixes. The table shows backticks inside excerpts as `'`. Full member copies live only in the git-ignored `evidence/extracted/`.

Reproduce with `node docs/apidog-auth/tools/scan-auth.cjs`. It writes `evidence/raw/auth-facts.json` (every fact with offset, module id, occurrence count and member SHA-256) and `evidence/raw/auth-term-hits.json` (a term census over all `dist/renderer` and `dist/main` top-level JS).

## Inferences (not directly proven; each cites facts)

- **I1. Type model.** Each request, folder or root stores an `auth` object of the form `{type, [type]: {...fields}}`. Credentials live under a key named after the type, for example `{type:"bearer", bearer:{token}}`. A separate `securityScheme` object holds references to reusable, OpenAPI-compatible scheme records. *(F01, F02, F04, F05, F55, F64)*
- **I2. Twelve concrete schemes.** The concrete schemes are apikey, bearer, jwt, basic, digest, oauth1, oauth2, hawk, awsv4, kerberos1, ntlm and edgegrid. There are four structural values: inherit, noauth, securityscheme and combination. `customize` is a security-scheme fallback for OAS schemes Apidog cannot type. There is **no `akamai` id** (Akamai is `edgegrid`). `asap` appears only in an import enum and is not accepted. *(F01–F03, F52, F59, F65)*
- **I3. API key.** The fields are `key`, `value` and `in`. Request-level auth supports `header` (the default) and `query` only. Neither the UI nor the runtime signer handles cookies, and an OAS `in: cookie` value has no matching UI option. *(F16–F18, F57, F61)*
- **I4. OAuth 2.0 browser flow.** In the desktop app, the renderer builds the authorization URL and sends it over IPC to the main process. When "Authorize using browser" (`useBrowserAuthorization`) is off, `OAuth2.StartLogin` is sent. The main process most likely opens an embedded window and matches the redirect against `redirect_uri` plus the expected `code`/`access_token` params and state. When the option is on, `OAuth2.StartExternalBrowserLogin` is sent. A random state is generated, and the redirect URI becomes the hosted `oauth2-browser-callback.html` page, which presumably hands the result back to the app. The result returns through `OAuth2.LoginCallback`. The main-process side is in bytecode, so the embedded-window and external-browser mechanics themselves are inferred from channel names. *(F22, F27, F31, F32)*
- **I5. Token endpoint calls do not run in the renderer.** The renderer builds the token and refresh requests as form-urlencoded POSTs. It executes them through the app's request runner, the same one used for normal sends, which communicates over IPC. Proxy, TLS and certificate settings therefore apply to token requests too. *(F25, F26, F29, F30)*
- **I6. Token storage is variable-based, not a separate vault.** The token goes into the `accessToken` field, ideally as a `{{var}}` reference. Its JSON detail (expiry, refresh token and so on) goes into the sibling variable `var:metadata`, saved as a local "CurrentValue". Before sending, the runner refreshes automatically when the token is within 60 s of expiry and a refresh_token exists. This applies only to the code, PKCE and password grants. The refreshed values are written back to the same variables. Client-credentials and implicit tokens are not auto-refreshed. *(F28, F33–F37, F39, F40)*
- **I7. Inheritance.** "Inherit" means: walk from the endpoint's folder up to the root, and the first non-inherit auth wins. A missing or empty auth also counts as inherit. The project or module **root folder** is the top level. If the root has no auth, the result is `noauth`. A folder set to inherit can override only the credential *values* of the inherited definition. The UI calls this "Use Parent's Default Credentials" vs "Set Manually". *(F10–F15, F62–F64)*
- **I8. OpenAPI import.** Every `components.securitySchemes` entry becomes a reusable SecurityScheme record that keeps the raw OAS object. The global `security` field is placed on the import root folder and operation `security` on each endpoint. Both become `{type:"securityscheme"}` plus groups that reference scheme names. An OR list becomes multiple groups, with the first one active. An AND requirement becomes a synthetic `combination` scheme. `[]` maps to inherit, while `[{}]` maps to noauth (a quirk: OAS treats `[]` as "no security"). Swagger 2.0 `securityDefinitions` reach this path after conversion to OAS 3. openIdConnect and mutualTLS map to `customize`, with no runtime auth. *(F44–F54, F57)*
- **I9. Credentials are template strings.** Every credential field can contain `{{variables}}`, which are rendered by the templating module before use. Secrets are protected by convention and policy, with no at-rest encryption found in the scanned JS. The mechanisms are: local-only variable values, Vault Secret references (`vault:` prefix), enterprise policies, and masking before AI features. *(F39–F43)*

## Implications for Reqora

1. **Data shape.** Store `auth = { type, [type]: config }` on requests, folders and the collection root. Treat an absent value, `{}` and `{type:"inherit"}` all as inherit. Resolve at send time by walking up to the root. The root default should be `noauth`. Record which ancestor supplied the definition so the UI can show "Inherited from <folder>/Root".
2. **Minimum viable set.** noauth, inherit, apikey (header/query, plus cookie as a Reqora extension if wanted), bearer (with a `{{access_token}}` default token), basic and oauth2. digest, oauth1, awsv4, hawk, ntlm and edgegrid can come later behind the same `{type,[type]}` contract.
3. **OAuth 2.0 fields.** Use the field names from F19/F20: grant_type, authUrl, accessTokenUrl, refreshTokenUrl, clientId, clientSecret, scope, state, redirect_uri, challengeAlgorithm (S256/plain), code_verifier, client_authentication (header/body), addTokenTo (header/queryParams), headerKey (Authorization), headerPrefix (Bearer), queryParamKey (access_token), useTokenType (access_token/id_token), auth/token/refresh request params with `send_as`, and useTokenConfigAsRefreshTokenConfig.
4. **OAuth 2.0 flow.** Run the token POST in the Electron main process (or Reqora's request engine), never in the renderer. For authorization code, prefer the system browser with a loopback redirect (RFC 8252) over an embedded window. Always generate `state` and verify it. Also offer an embedded-window option for IdPs that need it. Add a 120 s timeout and a cancel action.
5. **Token storage.** Persist the token detail with an issued timestamp. Refresh automatically when `now >= ts + expires_in - 60`. Keep tokens in local-only (non-shared, non-exported) storage. Encrypt at rest with Electron `safeStorage`, which is an improvement over what was observed.
6. **Variables in credentials.** Render `{{var}}` in every credential field before signing. Mark sensitive fields so exports and AI/diagnostic features can mask them.
7. **OpenAPI import.** Keep each `securitySchemes` entry as a reusable definition, mapping http bearer to bearer, basic to basic, apiKey to apikey (header/query, plus cookie if supported) and oauth2 flows to grant types. Apply operation `security` to the endpoint and global `security` to the root. Map `[{}]` to noauth. For `[]` on an operation, follow the OAS spec (noauth), and document that this deviates from Apidog.

## Limits

- `dist/main/main.jsc` and other `.jsc` files are V8 bytecode. The main-process handlers for `OAuth2.StartLogin` / `StartExternalBrowserLogin` (window creation, redirect interception, cookie clearing) were **not** read. I4 is an inference from channel names and renderer call sites.
- No dynamic run was performed. Defaults and flows are as coded, not observed.
- Duplicated chunks exist (the constants module 429350 appears in 55189, 64268, 73427, 77570, 82290, 94743). Only one copy is cited per fact.
- Server-side storage (whether the backend encrypts synced credentials) is outside the artifact.
- The Vault Secret providers (HashiCorp, Azure Key Vault, AWS Secrets Manager) were only located through locale strings and the `vault:` prefix check. Their resolution path was not traced.
- The per-scheme UI for digest, oauth1, hawk, awsv4, ntlm and edgegrid was only sampled. Field names come from the label map (F04/F05) and the oauth1 form.
