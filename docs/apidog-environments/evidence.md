Additional facts read in the same windows. They are not separate probes.

- **F-M04a** (`r/6874.a29ed692.async.js` @685, module 331553). `mergeVariables(remote, local)` maps each remote variable to `{name, initialValue: remote.value, isFixedValue, value: local?.value ?? remote.value ?? "", description: remote.description || local?.description || "", isBindInitial: !local || local.isBindInitial, securityType: remote.securityType, isSync: true}`. It then appends local variables with `isSync` false that are absent remotely. `mergeDefinition` applies the same rule to `parameters.{cookie,query,header,body}`.
- **F-M06a** (same member @3634). `getSplitVariables(list, field, isSync)` keeps entries whose `field` is defined and emits `{name, securityType, value: entry[field], description, initialValue, isSync}`. `isFixedValue` and `isBindInitial` are added only when truthy. Initial env = split on `"initialValue"`. Local env = split on `"value"` (only `id`, `projectId`, `variables`, `parameters`).
- **F-P01a** (`r/79064.22ac529e.async.js`, module 342987, @7000–9600). `getRenderContext` loads globals (`getGlobalsById`), team globals (`getTeamGlobalsById`), module globals (`getModuleGlobalsById(moduleId)`), vault values (`getVaultSecretValues`), and the environment, either by `environmentId` or via `getCurrentEnvironment`. Test data and temp variables come in as arguments. A caller-supplied `concatVariableDefinitions` list replaces all of this.
- **F-P04a** (same member @5100–5700). `buildRenderContext` copies each layer onto the accumulated object in order, so a later key overwrites an earlier one. Nested objects are merged recursively. Keys are then sorted so that values with no `{{`/`{%` come first, and up to 3 passes re-render each value against the merged context. A key is marked stable once rendering leaves it unchanged.
- **F-S10a** (same member @6092). `render(value, context, ignorePathRegex, errorMode="throw")` walks strings, arrays, and objects. It skips `Date/RegExp/Error/Boolean/Number/null/undefined` and any object with `disabled` set. When a string contains `{{…{{`, each innermost `\{\{[^{}]+\}\}` match is rendered from last to first and spliced in. Otherwise the whole string is rendered. The loop repeats until the output stops changing or 19 iterations pass.
- **F-S08a** (`r/80318.76475b49.async.js`, module 440205, @6600–7400). Before rendering, dynamic-value tags (`{{$...}}` / faker) are replaced with random ids. The string then goes through nunjucks (`autoescape:false`, `throwOnUndefined:true`). On any nunjucks error the pre-render string is used, and the ids are restored to the dynamic-value output or the original text. So one undefined variable leaves the whole string's `{{vars}}` unrendered (see inference I-6).
- **F-S09a** (same member @4355). The filters are `md5`, `sha`, `base64`, `unbase64`, `encodeURIComponent`, `decodeURIComponent`, `concat`, `lconcat`, `substr`, `number`, `padStart`, and `padEnd`. Template plugins are added as nunjucks extensions.
- **F-B01a** (`r/18375.66daf0bc.async.js`, module 501434). `getRequestBaseUrl({serverId, folderId, folderMap, rootFolderMap, moduleId, environment, servers, path})` works as follows:
  - It returns `""` when there is no environment, or the path starts with `{{`, `http://` or `https://`.
  - It returns `environment.baseUrls[serverId]` if that key is set.
  - If `serverId` is `""` or not in the project `servers` list, it walks up the folder chain via `parentId`, with cycle protection. At root (`folderId 0`) it uses `rootFolderMap[moduleId]`. When the chain yields nothing, it uses the module id when that id is a server, else `"default"`.
  - Finally it returns `baseUrls[resolved] || ""` when the resolved id exists in `servers`, else `baseUrls.default || ""`. WebSocket and Socket.IO use parallel `websocketBaseUrls`/`socketioBaseUrls` getters.
- **F-B04a** (`r/73427.2a071a7d.async.js`, module 84153, @15993–16900). In the HTTP request builder, path params are substituted first. Then:
  - If the path matches `^https?://` (or a proto scheme), it is used as-is.
  - Otherwise, a project association uses `getProjectAssociationBaseUrl`, a folder map uses `getRequestBaseUrl`, and in both cases `url = baseUrl + path`.
  - Otherwise, if the path starts with `/`, `url = environment.baseUrls.default + path`, where `baseUrls` defaults to `{default:"127.0.0.1"}`.
  - Otherwise the path is used unchanged. No slash normalization is done.
- **F-B05a** (same member @15050–15700). Common parameters are merged in. Then, for each environment parameter location, an environment param is added when no param with that key exists, or replaces the existing one when that one is disabled. Environment headers named `content-type` are skipped.
- **F-O08a** (`r/index…js` @213663). When a script updates an environment (`updateBySdk`), only `value` is taken from the script. `initialValue`, `isFixedValue` and `description` are kept from the stored variable. The local environment is written to `localEnvironment` under `"<projectId>.<envId>"`. Global variables follow the same pattern with `LocalGlobalVariables` (@222777).
- **F-L-tooltip** (`r/locale.en-US…` @183106). The full `environment.tooltip.securityType` text says Secret type variables are masked and "excluded when exporting data or publishing documentation".

## Inferences

These are interpretations of the facts above, not direct observations.

- **I-1: precedence (request rendering).** The render context is built by overwriting in the order vault → team globals → project globals → module variables → environment → test data → temporary/local (P01, F-P04a). The effective priority, from highest to lowest, is therefore **local/temp > test data > environment > module > global (project) > team > vault**. The script runtime (P06, P07) uses the same order through first-match-wins: `_variables` (local) > `data` > `environment` > `collectionVariables` (most likely the module variables) > `globals` > `teamGlobals`. Code generation (P09) agrees: module after global, environment last. The hover preview (P08) checks vault before team, which disagrees slightly with P01, where vault is lowest. Treat P01 as authoritative for sending.
- **I-2: initial vs current value.** Each variable has a shared `initialValue`, synced to the server, and a local `value`, stored on the device in `localEnvironment` / `localGlobalVariables` / `localTeamVariables` / `localModuleVariables`, keyed per project and environment (M04–M06, M11, M12, O02, L02). `isBindInitial` (default true for new rows, M08) means "local follows shared". The effective value is `isBindInitial ? initialValue : value` (P02, P07, X03). Script writes change only the local value (O08). Variables created locally carry `isSync: false` and survive merges (F-M04a).
- **I-3: substitution syntax.** Two engines exist. (a) The request renderer is nunjucks with `{{ }}`, `{% %}`, `{# #}`, filters with `|`, and strict undefined. A failed render leaves the text unrendered (S06–S08, F-S08a). (b) The script runtime/Substitutor uses `/\{\{([^{}]*?)}}/g`, repeats up to 19 times for nested results, and leaves unresolved tokens literally as `{{name}}` (S01–S03). Both accept JSON-path suffixes, `{{obj.a.b}}` and `{{arr[0]}}`, with an exact full-name match also allowed (S04, S05).
- **I-4: where substitution applies.** The renderer walks the whole request object, which covers URL, query, headers, body, auth and more. It skips disabled entries, and it can skip `body.*` when the "disable render request body" setting is on (S12, S13, F-S10a). The base URL is prepended *before* rendering, and only when the path does not start with `{{` or `http(s)://` (B01, B04).
- **I-5: environments carry services.** An environment holds `baseUrls` keyed by **server/service id**, with `"default"` always present, plus protocol variants, `variables`, and per-location `parameters` (M02, M03, L11–L13). The service list is project-level (`servers`): deleting a service removes it from every environment (L12). Endpoints and folders pick a service, or inherit it through the folder chain (B01–B03).
- **I-6: unresolved variables in the sender.** Because nunjucks runs in strict mode and falls back to the original string, an undefined variable leaves the literal `{{name}}` in the outgoing value. With `throwOnUndefined`, this probably holds for every token in that string, not only the undefined one. The UI flags it as "Unresolved Variable" (L17).
- **I-7: secrets.** "Secret" is a per-variable `securityType` (`"default"|"secret"`, L05) and not a separate scope. It drives masked display with an eye toggle (X01), exclusion from table search (X02), blanking in export/CLI configs (X03, L04), and per-key secret flags in the render context, probably for redacting history and logs (X07, P03). No evidence was found that local values are encrypted at rest (F-NEG). Vault secrets (HashiCorp Vault, Azure Key Vault, AWS Secrets Manager, Enterprise plan; L18) are fetched at render time, referenced as `{{vault:<name>}}` (X05, X06), and form the lowest-precedence layer.
- **I-8: active environment.** There is a single current environment id per project (O06). The sentinel `-1` means none (O01, O03, O07). When nothing is selected and exactly one environment exists, it is auto-selected (O05). The selector shows "Select environment" as a placeholder (L-locale `environment.environmentSelect.placeholder`). A literal "No Environment" option exists only in shared docs (`shareDocumentation.environment.none`). Sending a relative path without an environment falls back to the mock/default rules in B04, and some flows show "Please select an environment first." (L20).
- **I-9: operations.** These are create, update, update-local, delete, duplicate ("Duplicate", which copies the local values to the new id), reorder, import (Postman environments and globals), export (single or batch), and change-current (O01–O09, L07, L08). Mock and system environments cannot be duplicated or deleted (O09).

## Implications for Reqora

1. **Model.** `Environment {id, name, baseUrls: Record<serviceId,string> (must include "default"), variables: Variable[], parameters?: {header,query,cookie,body: Variable[]}}`. Add `Variable {name, initialValue, value, isBindInitial (default true), securityType: "default"|"secret", description, isFixedValue/required, enabled}`. Persist shared fields (`initialValue`, meta) in the workspace or collection file. Persist the current `value` in a separate per-user local store keyed `<projectId>.<envId>`, and merge them with the M04 rule.
2. **Precedence.** Use the same order, from highest to lowest: **local/temp (request or script) > test/iteration data > environment > module/collection > global > team > vault**. Implement it as an ordered list where the first match wins, or as a merge in the reverse order. The two are equivalent.
3. **Substitution.** For Reqora, pick one engine and document the choice. The minimal compatible option is regex `/\{\{([^{}]*?)}}/g` with the token trimmed. Resolve nested and recursive values up to 19 passes. Leave unresolved tokens as-is and surface them as "Unresolved Variable". Support `a.b` / `a[0]` path access on JSON values and exact dotted names. Apply it to URL, params, headers, body and auth, and skip disabled rows. Optionally offer Apidog-style nunjucks filters later.
4. **Base URL.** If the path is absolute (`http(s)://`) or starts with `{{`, do not prepend. Otherwise use `env.baseUrls[serviceId]`. An empty or unknown service id inherits through the folder chain, then the module, then `"default"`. Join by plain concatenation, and consider normalizing slashes as a deliberate improvement.
5. **Environment parameters.** Fill missing request params from the environment's `parameters`, and never override enabled request params or `content-type`.
6. **Secrets.** Add `securityType: "secret"`: masked input with a reveal toggle, excluded from search, blanked on export and share, redacted in history and logs. Apidog does not appear to encrypt local values at rest. Reqora can do better with Electron `safeStorage` for secret local values. That would be an addition, not mirrored behaviour. A vault (`{{vault:name}}`) is optional and later work.
7. **Active environment.** Store one current id per workspace, with `-1`/null meaning "No environment". Auto-select when exactly one exists. On delete of the current environment, reset to none.

## Limits

- Static reading only. Runtime behaviour such as nunjucks error paths and the exact `collectionVariables` mapping was not exercised. I-1, I-6 and the P08 vs P01 difference are inferences.
- Main-process code is V8 bytecode (`*.jsc`). The storage backend behind `localEnvironment` (`r/index…js` class `i`, an abstract key-value API) was not traced to disk, so the at-rest format and encryption are unknown beyond the negative string scan.
- Server-side behaviour cannot be observed: sync, duplicate (`s.YW`), and vault provider calls.
- Webpack module ids come from the nearest preceding module header. Hashed chunk names and offsets are specific to 2.8.50.
- `node_modules/@tarslib/*` members are readable library builds of the same logic. They were cited only where the renderer copy is minified beyond use (S01–S05, P07).
